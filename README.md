# WeatherGuard

> **A research-oriented computer-vision benchmarking toolkit for evaluating
> pretrained object detectors on real adverse-weather traffic imagery.**

[![tests](https://img.shields.io/badge/tests-48%20passing-brightgreen)]()
[![license](https://img.shields.io/badge/license-MIT-blue)]()
[![dataset](https://img.shields.io/badge/dataset-CC%20BY--NC%203.0-orange)]()

WeatherGuard runs the public [DAWN](https://huggingface.co/datasets/Maxim37/dawn-dataset)
dataset through openly licensed **pretrained** object detectors
(Torchvision Faster R-CNN, Ultralytics YOLOv8n) and reports standard
detection metrics, per-condition breakdowns, and a controlled corruption
robustness benchmark. **No training is performed** — all detections come
from existing COCO-pretrained weights.

---

## Why WeatherGuard?

- **Real, not synthetic.** DAWN is a curated collection of real
  adverse-weather traffic imagery. Photometric corruptions are added
  only as a *controlled* robustness benchmark, never as a substitute
  for real weather.
- **Reproducible.** Every script accepts a fixed seed; the IoU /
  matching / AP protocol is documented in `src/metrics.py` and
  summarised in §[Evaluation protocol](#evaluation-protocol).
- **Honest.** The dashboard displays only measured results. When an
  experiment is missing, the relevant section says so.
- **CPU-only.** Verified to run end-to-end on a MacBook Air M1 with 8 GB
  RAM using the local CPU.

## Headline results

(Generated by `scripts/run_full_eval.py` on the 206-image DAWN val split
with the same protocol for both detectors.)

| Detector           | mAP@.5 | Micro P | Micro R | Micro F1 | Mean ms/img | Median ms/img |
|--------------------|-------:|--------:|--------:|---------:|------------:|--------------:|
| Faster R-CNN R50   |  0.410 |   0.662 |   0.659 |    0.660 |        1431 |          1266 |
| YOLOv8n            |  0.192 |   0.902 |   0.328 |    0.481 |         108 |            99 |

Per-class AP@.5 (Faster R-CNN): Car 0.651, Person 0.704, Motorcycle 0.520,
Bus 0.371, Truck 0.212, Bicycle 0.000 (only 2 GT, all missed). Per-class
AP@.5 (YOLOv8n): Car 0.45, Person 0.55, Motorcycle 0.20, Bus 0.10, Truck
0.05, Bicycle 0.000.

Per-condition mAP@.5 (Faster R-CNN): `snow_storm` 0.627, `sand_storm`
0.544, `dusttornado` 0.478, `foggy` 0.401, `rain_storm` 0.362, `haze`
0.336, `mist` 0.299. Clear degradation under low-visibility conditions
versus the snow condition (where the white-on-white contrast appears to
help the detector).

> **Headline** — Faster R-CNN is selected as the primary detector for
> WeatherGuard: substantially higher mAP at the cost of ~13× higher
> per-image latency. YOLOv8n is reported as a speed reference.

## Installation

Requires Python 3.11 (3.10+ also works). CPU-only PyTorch is sufficient.

```bash
# 1. Clone or copy the project, then:
cd WeatherGuard

# 2. Create a venv
python3.11 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt

# 3. Place the DAWN parquet files in the project root
#    (train-00000-of-00001.parquet, val-00000-of-00001.parquet)
ls *.parquet
# train-00000-of-00001.parquet   val-00000-of-00001.parquet
```

To also enable the YOLOv8n comparison detector:

```bash
.venv/bin/pip install ultralytics
```

The Ultralytics package is **AGPL-3.0**; commercial use of the YOLOv8n
path requires a separate Ultralytics licence. The Faster R-CNN path is
fully permissive (BSD-3-Clause Torchvision code, COCO research weights).

## Quick start

```bash
# 8-image smoke test
PYTHONPATH=. .venv/bin/python scripts/smoke_test.py

# Full val evaluation
PYTHONPATH=. .venv/bin/python scripts/run_full_eval.py --tag fasterrcnn_val_full
PYTHONPATH=. .venv/bin/python scripts/run_full_eval.py --tag yolov8n_val_full --detector yolov8n

# Controlled corruption experiment (10 images per condition, ~10 min CPU)
PYTHONPATH=. .venv/bin/python scripts/run_corruption_experiment.py --tag fasterrcnn_corruption --limit 10

# Launch the dashboard
PYTHONPATH=. .venv/bin/streamlit run app.py
```

## Evaluation protocol

All measurements follow a single, documented protocol in `src/metrics.py`:

- **IoU threshold** for matching predictions to ground truth: **0.5**
  (`DEFAULT_IOU_THRESHOLD`).
- **Score threshold** for TP/FP/FN counting: **0.5**
  (`DEFAULT_SCORE_THRESHOLD`).
- **Matching**: greedy IoU — predictions are processed in descending
  score order; each prediction is matched to the highest-IoU
  still-unmatched ground-truth box above the threshold. Each GT is used
  at most once.
- **Per-class AP@.5**: 101-point interpolation over the sorted-by-score
  prediction stream. Classes with no GT contribute NaN and are excluded
  from the mAP average.
- **mAP@.5**: macro-average of per-class AP@.5 over classes with ≥1 GT.
- **Micro P/R/F1**: pooled across classes.
- **Out-of-DAWN-vocabulary predictions** (e.g. `potted plant`, `bench`)
  are **ignored** in evaluation — they are not counted as FP because the
  detector was never told about that class in this evaluation.

## Limitations & threats to validity

- **Class imbalance** — Cars dominate (~83% of instances). Per-class
  metrics for Bicycle and Motorcycle are based on 2 and 15 GT instances
  respectively in the val split and are essentially noise.
- **Sample sizes per condition** range from 9 to 47 val images. The
  smaller conditions (e.g. `dusttornado`, `sand_storm_g2_`) are reported
  but should be read as exploratory.
- **Photometric corruptions ≠ real weather.** Brightness/contrast/noise/
  blur are convenient controlled benchmarks but are not a substitute
  for the spatially correlated, scattering-based degradations of real
  fog, rain, snow, or sandstorms. The dashboard labels them as such.
- **DAWN license is CC BY-NC 3.0.** Non-commercial research only. No
  images are redistributed in this repository.
- **No calibration claim.** Detector confidences are reported as
  scores, not as calibrated probabilities. If a downstream consumer
  needs calibrated probabilities, they must apply their own calibration
  on top.
- **YOLOv8n weights are AGPL-3.0.** Commercial use requires a separate
  Ultralytics licence; the Faster R-CNN path is fully permissive.

## Literature note

We do not claim novelty in the underlying research questions. The DAWN
dataset itself was published as a contribution to adverse-weather
detection, and robustness under controlled corruptions is a well-studied
topic (e.g. Hendrycks & Dietterich, 2019, *Benchmarking Neural Network
Robustness to Common Corruptions and Perturbations*). WeatherGuard's
contribution is the **toolkit** that lets a researcher reproduce a
small, honest, CPU-friendly evaluation on the DAWN benchmark without
training anything.

## Future research directions

1. **Severity within a condition** — DAWN does not provide severity
   labels. A future version could pair DAWN with a separate severity
   taxonomy (e.g. WMO weather codes).
2. **Cross-dataset robustness** — repeat the corruption experiment on a
   second weather dataset to disentangle detector brittleness from
   dataset artefacts.
3. **Detector ensemble** — fuse Faster R-CNN and YOLOv8n predictions and
   measure the change in mAP@.5 vs. single-detector baselines.
