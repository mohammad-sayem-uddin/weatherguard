## 1. Objective & Threat Model

In synthetic datasets generated by diffusion models (such as Google Flow), slight prompt variations or adjacent seeds yield near-identical road textures, camera heights, and foreground vehicles across different weather conditions (e.g. generating the same highway template under Day, Fog, Rain, and Night).

If individual images are partitioned randomly or partitioned independently within each weather condition, identical spatial geometry leaks between Train and Test, inflating synthetic evaluation metrics while crippling real-world generalization.

Phase 3 independently validates the Disjoint Set Union (DSU) engine in [`scripts/create_d1_splits.py`](file:///Users/sayemuddin/Desktop/WeatherGuard/scripts/create_d1_splits.py) against adversarial test fixtures.

## 3. Algorithmic Invariants

1. **Global Transitive Closure:**
   The `DisjointSetUnion` algorithm computes the full connected components of the graph $G = (V, E)$, where edges $E$ include:
   - Shared `scenario_family_id`
   - Perceptual dHash near-duplicate edges ($\text{Hamming distance} \le 4$)
   Every connected component $C_k \subseteq V$ satisfies:
   $$\forall C_k: (C_k \subseteq S_{\text{train}}) \lor (C_k \subseteq S_{\text{val}}) \lor (C_k \subseteq S_{\text{test}})$$

2. **Zero Image-ID Overlap vs Connected-Component Isolation:**
   Checking that $S_{\text{train}} \cap S_{\text{test}} = \emptyset$ is necessary but insufficient. The validation explicitly checks that the cluster root sets are strictly disjoint:
   $$\text{Roots}(S_{\text{train}}) \cap \text{Roots}(S_{\text{test}}) = \emptyset$$

3. **Perceptual Hashing Audit:**
   The splitter consumes perceptual near-duplicate flags generated during the ingestion phase ([`scripts/ingest_weatherguard_d1.py`](file:///Users/sayemuddin/Desktop/WeatherGuard/scripts/ingest_weatherguard_d1.py)) using 64-bit difference hashing (`dHash`) with a threshold of $\le 4$ bits. This decouples computationally intensive pixel comparisons from rapid split partitioning.
